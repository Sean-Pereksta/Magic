# Sync game saves

After reconnecting, choose **Sync game saves** on an installed, supported title. The launcher opens the installed game under the selected local profile, using the same game files, local origin and save directory as **Play Offline**. Enter the save name and its password inside the game. A player can create a new named slot to retain two different journeys.

| Game | What travels | Game controls and conflict behavior |
| --- | --- | --- |
| Bramblebound | The complete saved profile, including expedition, kit and settings | Select **Firebase cloud saves** from the title. Reopen an existing slot before updating it in a new session. The game checks the encrypted record and revision in a transaction. Another device winning the write pauses cloud saving and keeps local progress. The game asks before replacing the local journey. After a successful save or confirmed reopen, the game can autosave changes while its session is linked. |
| Dwarf World | The saved world in DWGZ2 or legacy JSON format | Continue or start a world, then choose **☁ Save** to assign a slot. **Load Game** on the title screen reopens an existing world. The game checks the current slot password before a write. Large worlds use the game's encrypted chunks and manifest. Saving a linked world from the game also uploads in that session. Simultaneous edits have the game's existing last-write behavior. |
| Space Tyrants | The saved galaxy, including simulation and empire state | Continue or start a galaxy, then choose the cloud save button or **Save / Reopen** in the command hub. **Reopen Cloud Save** on the title is available without starting a new galaxy. Updating an existing slot requires its password. The game asks before replacing a running galaxy. Official saves update the slot, and 18-second simulation autosaves stay on the device. Simultaneous edits have the game's existing last-write behavior. |

All three games use their existing anonymous Firebase session and encrypted named records in the official project's Firestore `lobbies` collection. Each game calculates its own slot ID, encrypted payload, creation time, update time and server timestamp. The application neither copies game credentials into the Catnmice account nor queues unattended writes to these slots. A fresh game session may need the slot password again. Remaining installed titles retain their own local save behavior.

Ordinary offline play keeps external game traffic blocked. The dedicated save action permits only the three pinned Firebase modules, the project's anonymous authentication and token requests, and its default Firestore database's document read/write transports. Bramblebound also receives the public lobby config module copied from the pack's Magic revision, `5ab7ad915bb42a6c3064f0490911f28277edcafc`.
